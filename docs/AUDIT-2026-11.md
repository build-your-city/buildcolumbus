build-your-city.org), done on a branch from `main` at `41481d2` (PR #43
merged). It covers leftovers, security, performance, and quality.

Each finding is marked:

  visitors see, touches an outside service, or involves git history. Listed

- **OK:** checked and fine, no action needed.

**Visible to visitors (copy, layout, colors)**

1. **Small Build Blue labels fail contrast.** The 14px uppercase labels in
   Build Blue (`#3D8BFF`) are 3.31:1 on White and 2.94:1 on Paper. WCAG AA
   needs 4.5:1 for text this size. They are the speaker area labels on
   /hack and the weekday on event cards. Using `blue-deep` (`#0063F7`,
   4.51:1 on Paper) for small text would pass. Large blue text (the 56px
   step numbers) passes as large text on White only.
   **Decided: done.** Added `blue-text` (`#0056D6`, same hue as Build Blue):
   6.4:1 on White, 5.6:1 on Paper. It is used for the speaker labels, the
   event weekday, and link hover text. Small blue text on navy keeps Build
   Blue (5.2:1 on Ink), since any darker blue fails there. Large text and
   accents keep Build Blue. See `docs/DESIGN.md`.
2. **No 404 page.** Unknown paths like `/nope` render the header and footer
   with an empty middle, and Netlify returns 200 (a "soft 404") because of
   the `/* /index.html 200` SPA rule. A small not-found route with a link
   home would fix the experience. A real 404 status would need prerendering
   (see item 4).
   **Decided: done.** Both sites show a branded "Page not found" page with
   links back to the main pages. Netlify serves known pages with a 200 and
   everything else with a real 404 status (`/* /index.html 404`).
3. **/hack meta description is out of date.** It still says "builders from
   across Columbus spend a day working on real problems", while the hero now
   reads "we spend a day working on real problems". The /serve and /meetup
   descriptions were updated to match their heroes in PR #41; /hack was not
   in that request. It shows in search results, not on the page.
   **Decided: done.** "Once a year, we spend a day working on real problems
   in our city. Any skill is welcome. No code required."
4. **Per-page titles, descriptions and share cards only exist after
   JavaScript runs.** Both sites are client-rendered single-page apps.
   Google renders JavaScript, so per-page titles and descriptions work
   there, but social crawlers (Slack, Discord, LinkedIn, Facebook) see the
   static `index.html` for every page: `og:title` "Build Columbus" and
   `og:url` `https://buildcolumbus.org/` on every page. Prerendering the
   five routes at build time would fix this and the soft 404. That is a
   build change worth its own PR.
   **Decided: done.** Pages are listed once in `pages` in
   `sites/columbus/config/site.ts`. The build writes one HTML file per page
   with its own title ("Page | Build Columbus"; Home stays "Build
   Columbus"), description, canonical, and share tags, plus the Netlify
   rewrites and `sitemap.xml`. Page content still renders in the browser.
5. **`PhotoPlaceholder` is unused.** No page currently shows a placeholder,
   so the component is dead code today. It was kept because `CLAUDE.md` and
   `docs/DESIGN.md` describe placeholder boxes as the deliberate stand-in
   for a missing photo. Delete it if that workflow is retired.
6. **Design mockups are out of date.** `mockups/*.png` (6 files, the
   October 2026 design source referenced in `docs/DESIGN.md`) predate the
   copy pass and layout pass (they show eyebrows and the old section
   order). Keep them as history, replace them, or delete them. The
   duplicate source images under `mockups/images`, `mockups/logos`, and
   `mockups/speakers` were removed (see Leftovers).

9. **`LICENSE` copyright holder is "Christians in Tech".** Changing the

   **Decided: done.** The holder is now "Build Your City".
10. **Cross-site share images.** `scripts/og-images.mjs` writes both
    `og-columbus.png` and `og-build-your-city.png` into both sites' `public/`
    folders, so each site serves the other's image even though neither
    references it. Removing the extra copies could break a link someone has
    pasted elsewhere (for example in Meetup or social settings), so they were
    left.
11. **Security headers need a check on Netlify features.** The new headers
    (see Security) allow only what the site loads itself plus Google Fonts.
    If the Netlify projects use snippet injection, Netlify Analytics
    scripts, or forms, the Content-Security-Policy must allow them. Netlify's
    deploy-preview collaboration drawer is blocked by the policy on previews
    only; that is expected and harmless.
12. **HSTS is not on the preload list.** `Strict-Transport-Security` is set
    without `includeSubDomains` or `preload`, so it cannot break any
    subdomain served elsewhere (for example email or other services on the
    domain). Add both only after confirming every subdomain serves HTTPS.
    **Decided: keep as is.**
13. **Keeping pinned actions current.** Workflow actions are now pinned to
    commit SHAs. Turning on Dependabot for GitHub Actions (a small
    `.github/dependabot.yml`) would open PRs when new versions ship. It adds
    a GitHub service and recurring PRs, so it is your call.
    **Decided: done.** `.github/dependabot.yml` checks weekly (Mondays).
    npm minor and patch updates come grouped in one PR, majors as their own
    PRs; GitHub Actions updates come grouped in one PR.
14. **Deploy key scope.** The nightly sync pushes to `main` with the
    `SYNC_DEPLOY_KEY` deploy key so it can get past branch protection. A
    write deploy key can push to any branch and is not limited to
    `src/data/events.json`. Options: keep it (it only lives in Actions
    secrets), or switch to a GitHub App or a ruleset bypass limited to the
    bot. Check in GitHub settings that the key is marked as a deploy key for
    this repo only and that nobody else has a copy.
    **Decided: keep as is.**

15. **GitHub repo description says "The official website for Christians in
    Tech."** It is a repository setting on GitHub (About, on the repo's main
    page), not a file, so it is listed here. Suggested: "buildcolumbus.org
    and build-your-city.org".

### Security headers

Neither site set any security headers. Both `netlify.toml` files now set,
for every path:

- `Content-Security-Policy`: `default-src 'self'`, scripts and connections
  from the site itself only, styles from the site and
  `fonts.googleapis.com`, fonts from `fonts.gstatic.com`, images from the
  site plus `data:` (Vite inlines tiny assets), no plugins, no `<base>`
  changes, no form posts, `frame-ancestors 'none'`, and
  `upgrade-insecure-requests`.
- `Strict-Transport-Security: max-age=31536000` (Decision 12)
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY` (for old browsers; CSP `frame-ancestors` covers
  current ones)
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy` turning off camera, microphone, geolocation, payment,
  USB, and the Topics API (`browsing-topics`).

Hashed build assets under `/assets/*` also get a one-year immutable cache
header (Performance).

**How it was tested:** both built sites were served locally with exactly
the headers from their `netlify.toml` (and the SPA fallback), then every
page was loaded at 390px and 1280px in Chromium with a listener for CSP
violations. No violations or console errors; all four font weights and every
image loaded; client-side navigation between all pages, the mobile menu,
`robots.txt`, and `sitemap.xml` worked. The policy is therefore enforced,
not report-only. The Netlify deploy preview check is recorded in the PR.

## Performance

### Images

Source photos were up to 2380px wide and 780KB, and the two PNG speaker
headshots were 800x800 PNGs of about 760KB each, shown at 96px.

| Kind | Shown at (CSS px) | Before | After |
|---|---|---|---|
| Hero and split photos | up to 576 wide (desktop), full width on phones | 1400 to 2380 px wide | max 1400 px wide, JPEG quality 82, progressive |
| Program card photos | 345 wide | same files as above | same |
| Speaker and organizer headshots | 96 and 120 | 640 to 960 px; two PNGs at 760KB | 360 px square (3x), JPEG or WebP |
| Challenge-area icons | 64 | 520 px PNG | 192 px PNG (3x) |
| Sponsor logos | up to 56 tall, 200 wide | up to 2367 px wide | at most 168 px tall and 600 px wide (3x) |

Total image weight in `sites/columbus/images` went from **6.5MB to 2.2MB**
(the built `assets` folder from 6.7MB to 2.5MB). The heaviest single files:
the two PNG headshots went from about 760KB each to 9KB and 17KB (now
WebP, which keeps their transparent edges), and the hero photos from 520 to
780KB to 180 to 410KB. Screenshots of every page before and after match
(same page heights, under 0.1% of pixels different, all inside photos from
re-encoding).

- **Width and height attributes:** images have none, but every image box is
  already sized by CSS (an `aspect-*` ratio on photos, fixed sizes on
  headshots and icons, fixed-height logo cards), so the page does not shift
  when images load. **OK**
- **Lazy loading:** every image below the fold has `loading="lazy"`; each
  page's hero photo loads eagerly with `fetchpriority="high"`. **OK**
